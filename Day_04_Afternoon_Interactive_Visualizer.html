⚡ Scaled Dot-Product Attention
The core mathematical engine powering all modern Transformers

Before Transformers (Vaswani et al., 2017), sequence models processed tokens sequentially from left to right via RNNs, creating severe bottlenecking and vanishing gradients. Self-Attention computes direct, pairwise semantic relationships between every word in a sequence simultaneously in O(1) sequential steps.

The 3 Projections: Every input token embedding \(x_i\) is linearly multiplied by three trained weight matrices:
  • Query (\(Q\)): What the current token is looking for.
  • Key (\(K\)): What the target token contains / offers.
  • Value (\(V\)): The actual contextual information extracted.
# Minimal PyTorch Self-Attention in 4 lines def scaled_dot_product_attention(Q, K, V): scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(K.size(-1)) weights = torch.softmax(scores, dim=-1) return torch.matmul(weights, V), weights

📐 Master Formula: Scaled Dot-Product Attention (Vaswani et al., 2017)
Foundational Math
$$\text{Attention}(Q, K, V) = \text{softmax}\left( \frac{Q K^T}{\sqrt{d_k}} \right) V$$
Mathematical Term Definition & Linear Algebra Role Operational Purpose in Deep Learning
\(Q \in \mathbb{R}^{n \times d_k}\) Query matrix: Linear projection of the input sequence tokens. Represents the search queries ("What context am I looking for?").
\(K^T \in \mathbb{R}^{d_k \times n}\) Transposed Key matrix: Linear projection of all candidate tokens. The dot product \(Q K^T\) computes raw pairwise affinity scores between every token pair.
\(\frac{1}{\sqrt{d_k}}\) Scaling factor equal to square root of key projection dimension \(d_k\). Prevents Softmax Saturation: For large \(d_k\), dot products explode in magnitude, pushing softmax into near-zero gradient regions. Scaling stabilizes variance back to 1.0.
\(\text{softmax}(\cdot)\) Row-wise normalized exponential probability distribution. Converts raw dot-product scores into normalized attention weights summing to 1.0.
\(V \in \mathbb{R}^{n \times d_v}\) Value matrix: Linear projection of information content. Weighted average of value vectors forms the final context-aware output representation.
🧩 Step-by-Step Mathematical Walkthrough & Intuitive Mechanics
🔍 Where Did Everything in the Formula Come From?
Q (Query) "What I am searching for": Generated by multiplying input token vectors by learned weight matrix \(W_Q\). Represents a word actively seeking context (e.g., asking: "Who has attributes related to me?").
K (Key) "What attributes I have": Generated by multiplying input tokens by learned matrix \(W_K\). Represents the descriptor/label of candidate words (e.g., broadcasting: "I am a warm temperature descriptor").
K^T (K Transposed) Matrix Flip: We transpose the Key matrix so that the dot product \(Q K^T\) computes pairwise alignment scores between every Query vector and all Key vectors in one parallel matrix multiplication.
\(\sqrt{d_k}\) (Scaling Factor) The Variance Stabilizer: As dimension \(d_k\) increases, dot product magnitudes scale up as \(\mathcal{O}(d_k)\). Dividing by \(\sqrt{d_k}\) scales variance back to 1.0, preventing softmax from pushing into flat, zero-gradient saturation zones.
softmax(·) The Probability Splitter: Exponentiates and normalizes raw scores so they become non-negative attention weights strictly summing to 1.0 (100% total attention budget).
V (Value) "The Actual Information": Generated by multiplying input tokens by learned matrix \(W_V\). Once words determine their mutual relevance via \(Q K^T\), they take a weighted blend of these Value vectors to build contextualized representations.
🎯 Concrete Numerical Toy Example: "Hot sun"

Let us trace how the word "sun" gathers context from the word "Hot" and itself with projection dimension \(d_k = 4 \implies \sqrt{d_k} = \sqrt{4} = 2\):
• "Hot" has Key \(K_{ ext{Hot}} = [2, 2, 0, 0]\) and Value \(V_{ ext{Hot}} = [10, 0]\) (Semantic meaning: "Heat & Energy")
• "sun" has Query \(Q_{ ext{sun}} = [2, 1, 0, 0]\), Key \(K_{ ext{sun}} = [0, 2, 0, 0]\), and Value \(V_{ ext{sun}} = [0, 10]\) (Semantic meaning: "Bright Celestial Body")

Step 1 Compute Raw Pairwise Matching Scores (\(Q K^T\))
Multiply "sun's" Query against each word's Key via dot products:
Match with "Hot": (2 × 2) + (1 × 2) + (0 × 0) + (0 × 0) = 4 + 2 = 6
Match with "sun": (2 × 0) + (1 × 2) + (0 × 0) + (0 × 0) = 0 + 2 = 2
Raw unscaled attention scores: [6, 2]
Step 2 Scale by \(\sqrt{d_k} = 2\)
Scale scores down by \(\sqrt{d_k} = 2\) to prevent softmax gradient vanishing:
Score for "Hot": 6 ÷ 2 = 3
Score for "sun": 2 ÷ 2 = 1
Scaled attention scores: [3, 1]
Step 3 Apply Softmax Normalization
Convert scaled scores into normalized probability distribution using natural exponents \(e^3 pprox 20.085\) and \(e^1 pprox 2.718\) (Sum \(pprox 22.803\)):
Attention Weight for "Hot": 20.085 ÷ 22.803 ≈ 0.88 (88% attention)
Attention Weight for "sun": 2.718 ÷ 22.803 ≈ 0.12 (12% attention)
Attention weight vector: [0.88, 0.12] (sums to exactly 1.0)
Step 4 Weighted Sum of Value Vectors (\( imes V\))
Multiply each word's Value vector by its attention weight and sum together:
From "Hot": 0.88 × [10, 0] = [8.8, 0.0]
From "sun": 0.12 × [0, 10] = [0.0, 1.2]
Final Contextual Vector: [8.8, 0.0] + [0.0, 1.2] = [8.8, 1.2]
💡 Final Semantic Transformation: Prior to self-attention, "sun" was just an isolated token [0, 10]. After attention, "sun" incorporated 88% thermal information from "Hot", producing the blended contextualized vector [8.8, 1.2] — representing a "hot, bright sun"!
📐 Master Formula: Multi-Head Attention (MHA)
Parallel Representation
$$\text{MHA}(Q, K, V) = \text{Concat}(\text{head}_1, \text{head}_2, \dots, \text{head}_h) W^O \quad \text{where} \quad \text{head}_i = \text{Attention}(Q W_i^Q, K W_i^K, V W_i^V)$$
Formula Component Mechanics Why Multi-Head Outperforms Single Head
\(\text{head}_i\) Individual attention projection head running in dimension \(d_k = d_{model} / h\). Allows the network to attend to information from different representation subspaces simultaneously (e.g., Head 1 tracks syntax, Head 2 tracks coreference).
\(W_i^Q, W_i^K, W_i^V\) Learned linear projection parameter matrices per head. Projects \(d_{model}\) dimensional inputs into specialized subspace representations.
\(\text{Concat}(\dots) W^O\) Concatenation of all \(h\) head outputs followed by output projection \(W^O\). Integrates multi-perspective contextual signals back into the standard model dimension \(d_{model}\).
🔍 BERT: Bidirectional Encoder Representations
Deep bidirectional context understanding pioneered by Google (Devlin et al., 2018)

Unlike unidirectional models that read text strictly left-to-right, BERT is an Encoder-Only architecture that conditions simultaneously on both left and right context in all layers. It reads the full sentence holistically, making it exceptionally powerful for text classification, question answering, and NER.

The 3-Embedding Input Representation:

Every input token to BERT receives the exact sum of three distinct embedding vectors:

Input Embedding = Token_Embed + Segment_Embed + Position_Embed

📐 Master Formula: BERT 3-Embedding Input Representation
Input Vector Summation
$$E_{\text{input}}(x_i) = E_{\text{token}}(w_i) + E_{\text{segment}}(s_i) + E_{\text{position}}(p_i)$$
Embedding Vector Dimension & Lookup Mechanism Operational Function in Bidirectional Processing
\(E_{\text{token}}(w_i) \in \mathbb{R}^{d_{model}}\) WordPiece subword vocabulary lookup (30,522 tokens). Encodes atomic lexical semantic identity. Subwords eliminate Out-Of-Vocabulary (OOV) errors.
\(E_{\text{segment}}(s_i) \in \mathbb{R}^{d_{model}}\) Binary learned segment indicator vector (\(s_i \in \{0, 1\}\)). Distinguishes Sentence A from Sentence B during cross-sentence tasks like QA and NLI.
\(E_{\text{position}}(p_i) \in \mathbb{R}^{d_{model}}\) Learned spatial position embedding vector (\(p_i \in [0, 511]\)). Injects deterministic sequence order, compensating for the Transformer's natural permutation invariance.
📐 Master Formula: Masked Language Model (MLM) Objective
Self-Supervised Pretraining
$$\mathcal{L}_{MLM}(\theta) = -\sum_{i \in \text{Masked}} \log P(x_i \mid \tilde{X}; \theta) \quad \text{subject to the 80/10/10 Rule}$$
Component / Rule Mechanics Why It Prevents Training Degradation
80% [MASK] Tokens Selected token is replaced by the literal special token [MASK]. Forces BERT to infer masked semantics strictly from surrounding bilateral context.
10% Random Tokens Selected token is replaced by an arbitrary random word from the dictionary. Forces the network to maintain continuous contextual vigilance: it cannot assume every unmasked token is correct.
10% Unchanged Tokens Selected token is kept completely unaltered. Prevents representation bias toward [MASK] tokens, ensuring representations remain faithful to real tokens during downstream fine-tuning.
Next Sentence Prediction (NSP) Binary classification on [CLS] token: Is Sentence B the actual subsequent sentence? Teaches BERT cross-sentence relational coherence essential for QA and natural language inference (NLI).

✍️ GPT: Generative Pre-trained Transformer
Autoregressive causal language generation developed by OpenAI (Radford et al., 2018–2023)

While BERT is an Encoder-Only model designed to understand existing text, GPT is a Decoder-Only model engineered to generate new text token-by-token. It operates under a strict Causal Mask: each token can only attend to previous tokens and itself, never to future tokens.

The Causal Masking Invariant:

To prevent the model from 'cheating' by looking ahead during training, an upper-triangular mask of \(-\infty\) is added to the attention scores before softmax: $$\text{Mask}_{i, j} = \begin{cases} 0 & \text{if } j \le i \\ -\infty & \text{if } j > i \end{cases}$$ Since \(e^{-\infty} = 0\), future token weights become strictly zero!

📐 Master Formula: Autoregressive Next-Token Causal Objective
Autoregressive Loss
$$\mathcal{L}_{GPT}(\theta) = -\sum_{i=1}^{n} \log P(u_i \mid u_{i-k}, \dots, u_{i-1}; \theta)$$
Symbol / Term Mathematical Definition Operational Function in LLM Training
\(u_i\) The ground-truth target token at position \(i\). The next token that the model is tasked with predicting.
\(u_{i-k}, \dots, u_{i-1}\) The preceding context window of up to \(k\) prior tokens. The historical prompt condition informing the prediction.
\(-\log P(\cdot)\) Negative log-likelihood cross-entropy loss. Minimizing this loss maximizes the predicted probability of the true next token occurring in human text.
\(\text{Temperature } T\) Logit scaling factor: \(P(u_i) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}\). \(T \to 0\) collapses to greedy deterministic selection; higher \(T\) flattens probabilities, generating creative/diverse responses.
🧩 Step-by-Step Mathematical Walkthrough & Intuitive Mechanics
🔍 Where Did Everything in the Formula Come From?
\(u_i\) Target Next Token: The authentic upcoming word in the training corpus that the model must predict.
\(u_{i-k}, \dots, u_{i-1}\) Strict Historical Context: The preceding \(k\) tokens. Unlike BERT which sees both left and right context, GPT's causal triangular mask strictly forbids attending to future tokens (\(j > i\)), enforcing natural temporal text generation.
\(-\sum \log P(\cdot)\) Cumulative Sequence Loss: Sum of negative log probabilities across all tokens in the document. Lower loss means the model predicts fluent, coherent, human-like text continuations.
🎯 Concrete Numerical Toy Example: Generating "Artificial Intelligence is powerful"

Let us trace two consecutive autoregressive next-token prediction steps:
• Step A: Context = "Artificial" → Target = "Intelligence"
• Step B: Context = "Artificial Intelligence" → Target = "is"

Step 1 Predict "Intelligence" Given "Artificial"
Softmax probability over 50,000 vocab tokens yields \(P( ext{"Intelligence"}) = 0.85\):
Loss_A = -ln(0.85) = 0.1625
Step 2 Predict "is" Given "Artificial Intelligence"
Next forward pass with appended context yields \(P( ext{"is"}) = 0.70\):
Loss_B = -ln(0.70) = 0.3567
Step 3 Compute Sequence Cross-Entropy & Perplexity
Average token cross-entropy loss:
Average Loss = (0.1625 + 0.3567) ÷ 2 = 0.2596
Perplexity = e^{0.2596} ≈ 1.296 (Model is choosing between ~1.3 plausible words!)
💡 The Role of Temperature \(T\): Logits are scaled as \(z_i / T\) before softmax. When \(T o 0.1\) (cold), the highest logit dominates completely (greedy, deterministic factual output). When \(T o 1.2\) (warm), the probability distribution flattens, giving lower-ranked tokens a chance to be picked (creative storytelling and diverse brainstorming).

🔍 Where Did Everything in the Formula Come From?
\( ilde{X}\) Corrupted Sequence: The input sentence where 15% of tokens are chosen for masking: 80% replaced with [MASK], 10% replaced with a random vocabulary token, and 10% left unchanged.
\(x_i\) True Ground-Truth Token: The authentic original word that was masked out.
\(P(x_i \mid ilde{X}; heta)\) Predicted Probability: The probability score assigned to the true word \(x_i\) after passing the final Transformer hidden state through a linear classification head and softmax over all 30,522 vocabulary tokens.
\(-\log P(\cdot)\) Cross-Entropy Surprise Penalty: If the model is 100% confident in the correct word (\(P=1.0\)), \(-\log(1.0) = 0\) (zero penalty). If the model predicts low probability (e.g. \(P=0.01\)), \(-\log(0.01) = 4.6\) (massive penalty!).

📈 Neural Scaling Laws & Emergent Abilities
Kaplan et al. (2020) and Chinchilla (Hoffmann et al., 2022) discoveries
Power-Law Predictability:

Loss scales as a predictable power law with parameter count \(N\), dataset size \(D\), and compute budget \(C\): $$L(N, D) \approx \left(\frac{N_c}{N}\right)^{\alpha_N} + \left(\frac{D_c}{D}\right)^{\alpha_D}$$ Increasing parameters and tokens predictably reduces cross-entropy loss across orders of magnitude!

Emergent Abilities:

Abilities not present in smaller models (multi-step arithmetic, symbolic code debugging, theory of mind) spontaneously emerge beyond critical parameter thresholds (~10B to 70B parameters) when trained on high-token budgets.

🚀 Parameter-Efficient Fine-Tuning (PEFT) & LoRA
Adapting 70B LLMs without retraining billions of weights (Hu et al., Microsoft 2021)

Full fine-tuning of modern foundation models requires updating hundreds of gigabytes of weights, demanding massive clusters of 80GB H100 GPUs. LoRA (Low-Rank Adaptation) freezes the pre-trained model weights \(W_0\) and injects small, trainable rank decomposition matrices into each Transformer layer.

Key Mathematical Principle:

Weight updates \(\Delta W\) have a very low intrinsic rank! Instead of training \(d \times k\) parameters, we factorize: $$\Delta W = B \times A \quad \text{where } B \in \mathbb{R}^{d \times r}, \; A \in \mathbb{R}^{r \times k}, \; r \ll \min(d, k)$$ For a \(4096 \times 4096\) weight matrix and rank \(r=8\), parameters drop from 16,777,216 to 65,536 (99.6% reduction)!

# Minimal LoRA Adapter in PyTorch class LoRALayer(nn.Module): def __init__(self, in_dim, out_dim, rank=8, alpha=16): super().__init__() self.A = nn.Parameter(torch.randn(rank, in_dim) * 0.01) self.B = nn.Parameter(torch.zeros(out_dim, rank)) self.scaling = alpha / rank def forward(self, x): return (x @ self.A.T @ self.B.T) * self.scaling

📐 Master Formula: LoRA Forward Pass & Low-Rank Decomposition
PEFT Mathematics
$$h = W_0 x + \Delta W x = W_0 x + \frac{\alpha}{r} (B A) x$$
Term / Symbol Dimension & Definition Operational Significance
\(W_0 \in \mathbb{R}^{d \times k}\) Frozen base pretrained weight tensor. Zero Gradient Computation: Remains completely frozen, saving backward pass activation memory and preserving base knowledge.
\(B \in \mathbb{R}^{d \times r}\) Trainable low-rank matrix initialized to all zeros. Ensures \(\Delta W = B \times A = 0\) at the very start of training, so model output is initially identical to base model.
\(A \in \mathbb{R}^{r \times k}\) Trainable low-rank matrix initialized with Gaussian \(\mathcal{N}(0, \sigma^2)\). Compresses the input representation into a compact \(r\)-dimensional bottleneck subspace.
\(\frac{\alpha}{r}\) Constant scaling factor with hyperparameter \(\alpha\). Stabilizes optimization when varying rank \(r\), eliminating the need to retune learning rates when rank changes.
🧩 Step-by-Step Mathematical Walkthrough & Intuitive Mechanics
🔍 Where Did Everything in the Formula Come From?
\(W_0 \in \mathbb{R}^{d imes k}\) Frozen Pre-Trained Foundation Weights: The massive base model weight table (e.g. \(4096 imes 4096 = 16.7 ext{M}\) parameters per layer). Frozen solid: zero gradient backprop, zero optimizer states, zero risk of catastrophic forgetting.
\(A \in \mathbb{R}^{r imes k}\) Trainable Down-Projection Bottleneck: Initialized with Gaussian random noise \(\mathcal{N}(0, \sigma^2)\). Compresses full input dimension \(k\) down to a tiny intrinsic rank \(r\) (e.g. \(r=8\) or \(r=16\)).
\(B \in \mathbb{R}^{d imes r}\) Trainable Up-Projection Expansion: Initialized to ALL ZEROS. Expands the rank-\(r\) bottleneck back up to full output dimension \(d\). Because \(B=0\) at step 0, \(\Delta W = B imes A = 0\), guaranteeing the model starts identically to the base pretrained model!
\( rac{lpha}{r}\) Scaling Constant: Hyperparameter constant (typically \(lpha = 2r\)). Stabilizes gradient optimization when experimenting with different rank values \(r\), avoiding the need to retune learning rates.
🎯 Concrete Numerical Toy Example: \(d=2, k=2\), Rank \(r=1\), and \(lpha=1\) (\(lpha/r = 1.0\))

Input token activation vector: \(x = [2, 3]\)
Frozen base weights: \(W_0 = egin{bmatrix} 1 & 0 \ 0 & 1 \end{bmatrix}\) (Identity matrix)
Trainable low-rank adapter matrices:
• Down-matrix \(A = [1, 2]\) (Dimension \(1 imes 2\), compresses 2D down to rank \(r=1\))
• Up-matrix \(B = egin{bmatrix} 0.5 \ 0.5 \end{bmatrix}\) (Dimension \(2 imes 1\), expands rank \(r=1\) back to 2D)

Step 1 Compute Base Model Forward Path (\(W_0 x\))
Pass input through frozen base weights without computing any gradients:
W_0 x = [[1, 0], [0, 1]] × [2, 3]^T = [2, 3]
Step 2 Compress Through Bottleneck Adapter (\(A x\))
Project input into the compact \(r=1\) subspace:
A x = (1 × 2) + (2 × 3) = 2 + 6 = 8 (A single scalar number!)
Step 3 Expand Bottleneck Back to Full Dimension (\(B imes (Ax)\))
Multiply compressed scalar by up-projection matrix \(B\):
B × 8 = [0.5 × 8, 0.5 × 8]^T = [4, 4]
Step 4 Scale & Sum with Base Model Path
Scale by \(lpha / r = 1.0\) and add adapter delta to base output:
Final Output h = W_0 x + (α/r)(B A x) = [2, 3] + [4, 4] = [6, 7]
💡 Production Magic (Zero Serving Latency): In full fine-tuning, storing weights + gradients + Adam momentum for a 70B model requires over 800GB of VRAM! LoRA only trains \(A\) and \(B\) (reducing parameters by >99%). When deployment time arrives, we compute \(\Delta W = rac{lpha}{r}(B imes A)\) once, add it directly into \(W_0\) permanently (\(W_{ ext{deploy}} = W_0 + \Delta W\)), and discard the adapter branches entirely — yielding ZERO extra inference latency!
